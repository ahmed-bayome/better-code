YAGNI — “You Aren’t Gonna Need It.”

Rule: **Do not build something until the current requirement actually needs it.**

For the coding rules:

* No speculative abstractions.
* No utilities “for future use.”
* No generic wrappers without a current use case.
* No configuration for hypothetical requirements.
* No extra layers just because they are considered “clean architecture.”
* Solve the current problem directly.
* Duplicate a small amount of code rather than introducing an abstraction prematurely.
* Refactor when real repetition or complexity appears.
* Every abstraction must have a concrete current consumer.

**Mindset:**

> Build what is needed now. Let future requirements earn their complexity.
